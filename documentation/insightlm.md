### Technologies Used in Insights LM

Insights LM is a full-stack web application cloning Google's Notebook LM, built primarily through "vibe coding" (AI-assisted development). It leverages a combination of no-code/low-code tools, cloud services, AI APIs, and open-source libraries. Below, I'll break it down by category, based on the development process described in the demo. This includes the core stack for the public version (using cloud AI services) and notes on the local/private version where applicable.

### 1. **Front-End Development**

- **Lovable**: The primary tool for building the UI and initial app structure. It's an AI-powered coding platform that generates React-based JavaScript code from prompts, screenshots, and iterative instructions. It handles layouts (e.g., dashboard, notebook interface, chat, sources panel, studio with notes and audio), state management, and integration with Supabase. Lovable also supports visual editing (e.g., deleting elements like "Discover" buttons) and version restoration for undoing changes.
    - Framework: React (generated by Lovable).
    - Language: JavaScript.
    - Key Features Built: Login/logout, dashboard with notebook cards (auto-generated titles, descriptions, icons, colors), file upload pop-ups, chat interface with citations (clickable links jumping to document sections), notes editor (editable/user notes vs. read-only AI responses), audio player (with play/pause, seek, volume, download/delete).
- **Tailwind CSS**: Used for styling (e.g., dynamic background colors for notebook cards based on AI-generated classes like `bg-red-500`).
- **Real-Time Updates**: Supabase real-time subscriptions for live UI refreshes (e.g., chat history, audio URL availability).

### 2. **Back-End and Workflow Automation**

- **n8n**: An open-source workflow automation tool for handling complex backend logic without writing much custom code. It's used for processing pipelines, API integrations, and asynchronous tasks to avoid timeouts in Supabase edge functions.
    - Key Workflows:
        - Document processing: Chunking PDFs/text/MP3s, embedding with AI models, upserting to vector store.
        - RAG (Retrieval-Augmented Generation): Querying vector stores for chat responses with citations (source ID, line numbers).
        - Notebook details generation: AI-based titles, descriptions, icons, colors, example questions.
        - Chat handling: AI agent with memory (stored in Supabase via PostgreSQL), tools for vector retrieval.
        - Podcast generation: Script creation via LLMs, audio synthesis, conversion (PCM to MP3 via FFmpeg), upload to Supabase.
    - Integrations: HTTP requests for APIs, switches for file types (e.g., PDF extraction, MP3 transcription), code nodes for custom logic (e.g., extracting notebook IDs).
    - Authentication: Custom headers for secure webhook calls.
    - License Note: Uses a sustainable use license (free for internal use; enterprise for SaaS).
- **Supabase Edge Functions**: Serverless JavaScript functions for quick tasks like triggering n8n webhooks, handling authentication, and callbacks. Examples: `generate_notebook_content`, `process_document`, `send_chat_message`. They bridge the front-end to n8n and enforce timeouts (e.g., 150-400 seconds limit, leading to async designs).
- **FFmpeg**: Command-line tool (installed in n8n/Docker) for audio conversion (e.g., raw PCM from Gemini to MP3).

### 3. **Database and Storage**

- **Supabase**: Open-source Firebase alternative (built on PostgreSQL) for all data persistence and auth.
    - Authentication: User login/signup (email/password), row-level security (RLS) policies to ensure users only access their data.
    - Database: PostgreSQL tables like `notebooks` (titles, descriptions, audio URLs), `sources` (files, summaries, processing status), `documents` (vector embeddings), `n8n_chat_histories` (chat memory).
    - Storage: Buckets for files (e.g., `sources` for uploads, `audio` for podcasts). Private buckets with signed URLs for secure access.
    - Extensions: PG Vector for vector embeddings (similarity search in RAG).
    - Real-Time: Subscriptions for live updates (e.g., chat messages, audio ready).
- **Vector Store**: Supabase with LangChain integration for storing document chunks (content, metadata like notebook/source IDs, line numbers).

### 4. **AI and Machine Learning Integrations**

- **OpenAI APIs**:
    - Models: GPT-4o mini (title/summary generation), GPT-4o (chat responses), text-embedding-3-small (document embeddings).
    - Features: Chat completions, embeddings for RAG, transcription (Whisper for MP3s).
- **Anthropic Claude**: Claude 3.5 Sonnet for some chat responses (better reasoning in demos).
- **Google Gemini**: Gemini 1.5 Flash (preview) for multi-speaker text-to-speech in podcast generation.
- **Local AI (in Private Version)**:
    - Ollama: For local embeddings and inference (replaces OpenAI/Gemini).
    - Whisper: Local container for audio transcription.
    - Piper TTS: For text-to-speech in podcasts (replaces Gemini).
- **LangChain**: Quick-start queries in Supabase for vector store setup (e.g., `documents` table, `match_documents` function).
- **Embeddings and RAG**: Recursive character text splitter (chunk size 1000, overlap 200); tools like Supabase vector store retrieval in n8n AI agents.
- **Output Parsers**: Structured parsers in n8n for JSON responses (e.g., citations with indices, source IDs, lines).

### 5. **File and Media Processing**

- **Extractors**: n8n nodes for PDFs (extract text), text files (direct reading), MP3s (transcription via OpenAI Whisper or local equivalent).
- **Switches and Routers**: n8n for handling file types based on MIME (e.g., `application/pdf`, `audio/mpeg`, `text/plain`).
- **Metadata Handling**: Custom fields in vectors (e.g., notebook ID filtering to scope queries).

### 6. **Deployment and Infrastructure**

- **GitHub Repos**: Two versions:
    - Public: Deployable to Vercel/Netlify (React app); uses cloud AI.
    - Local/Private: Dockerized (Compose file for n8n, Supabase, Ollama, Whisper, Piper TTS). Runs offline for data privacy.
- **Hosting**: Bolt.new (competitor to Lovable) for quick deployment; any React host works.
- **Docker**: For local setup (containers for all services).
- **Secrets Management**: Supabase vaults for API keys (e.g., OpenAI, Gemini) and webhook URLs.

### 7. **Additional Libraries and Utilities**

- **Python Libraries (in n8n/local)**: For advanced processing (e.g., NumPy/SciPy if needed, but not heavily used here).
- **HTTP Requests**: In n8n for API calls (e.g., signed URLs, uploads).
- **Error Handling**: Retries in n8n agents (e.g., 3 retries with 5s delay for overloads).

This stack emphasizes rapid prototyping (via Lovable/n8n) while being extensible (e.g., swap AI providers). The public version relies on cloud APIs for speed/cost, while the local one prioritizes privacy with on-device processing. Total build time: ~3 days, as per the demo.
